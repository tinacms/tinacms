Other sourced facts used in the narration:

- The TinaCloud integration is required when the deploy button lists it: https://vercel.com/docs/deploy-button ("the corresponding Integrations are required to be installed for the Vercel Project").
- Vercel build logs: "click the Build Logs button from the production deployment tile in the projects overview page": https://vercel.com/docs/deployments/logs.
- Cloudflare build logs live under the Worker's Deployments tab ("View build history"); TinaCloud's "View build log" link opens the build: https://developers.cloudflare.com/workers/ci-cd/builds/.
- Cloudflare's deploy page lets the user set the repository name and Worker name: https://developers.cloudflare.com/workers/platform/deploy-buttons/.
- The Vercel badge (`deploy-vercel.svg`) is from https://vercel.com/button; the Cloudflare badge (`deploy-cloudflare.svg`) is from https://deploy.workers.cloudflare.com/button. Both are the hosts' published embed badges.
- The tina.io Vercel page (https://tina.io/docs/tinacloud/deployment-options/vercel) covers manual Vercel setup and does not describe the TinaCloud integration; the V2 wording follows the dashboard's own Vercel copy and the Vercel deploy-button docs instead.
- `unconfirmed`: how the Vercel tab returns to TinaCloud after the build (V3), automatically or after a click on Vercel's last page.

## Where the source differs from the spec

- **S3, V1, C1, S2 page header:** every starter-page and Cloudflare-setup still also shows the page header "New Project", which the spec did not quote.
- **C2 GitHub row:** the spec quotes the row as "Not connected" with "Connect GitHub"; the still shows the waiting state only, where "Connect GitHub" stays visible but disabled (per the critique).
- **C5 secrets prompt:** the spec has C5 show a secrets prompt left empty. The Next.js starter's `.env.example` (https://github.com/tinacms/tina-nextjs-starter/blob/main/.env.example) comments out every line and says the Deploy to Cloudflare button only turns uncommented lines into required secrets, so Cloudflare likely shows no secrets prompt for it. C5 shows no secrets section; the narration says "If Cloudflare asks for secrets, leave them empty". TinaCloud's own step text still says "Skip the secrets prompt."
- **C8 row 2** reads "Read its GitHub repo from Cloudflare and created your TinaCloud project" with the repo `your-github/my-tina-site` beside it (the spec called it "the repo/project row").
- **C7 row 4** reads "TinaCloud indexed your repo" while still pending: the source shows that wording in every phase except indexing.
- **C6** has no subtitle; the heading is "We found new Workers. Which one is yours?" and each row has a "Created" time and "Use this Worker", with "Back" below.
- **S3** "Cloudflare (coming soon)": the selected Next.js Starter supports Cloudflare, so the label is not on the still; the narration describes it without quoting it.

## Contrast adjustments

To keep body text at 4.5:1 or better on 1080p video, links use blue-600 (`#2563eb`) instead of the dashboard's blue-500, and upcoming wizard labels and dots use gray-500 instead of gray-400. Everything else uses the dashboard's colours.

## Not a TinaCloud string

The S1 and S4 title cards, the V6 annotation labels, browser tabs and URL bars are video graphics, not dashboard text. The GitHub link beside the starter name is drawn as a neutral repository icon, since the folder carries no third-party logos other than the two deploy badges.
